Configuration¶

meta-qcom is configured through kas files, the layer’s BitBake configuration, variables that its classes and machine includes read, and a few environment variables for the helper scripts.

How settings combine¶

kas-container build takes kas files joined with :, such as ci/rb3gen2-core-kit.yml:ci/qcom-distro.yml:ci/linux-qcom-6.18.yml. Each file adds to or overrides the files before it, and header.includes pulls in other files first, as the kas project configuration describes. kas writes every local_conf_header entry into conf/local.conf, so those lines follow BitBake’s assignment rules: ?= and ??= set defaults that a plain = elsewhere replaces, and :append, :remove, and += adjust a value. Standard variables are defined in the Yocto Project variable glossary; the tables below explain this layer’s choices.

The helper scripts read the environment variables listed with safe examples in .env.example. Nothing loads that file automatically; export the values in your shell.

Repository settings¶

File

Settings

.gitignore

Ignores Python caches, the CI-generated ci/build-id.yml, a local kas-container copy, .env files except .env.example, and the documentation environment and intermediates.

.github/CODEOWNERS

Assigns the layer maintainers to all paths and the CI maintainers to ci/.

.github/.markdownlint.yaml

Turns off the line-length and inline HTML rules, allows repeated headings in different sections, and requires a first-line heading.

issue templates

Each template’s front matter names it (name) and says when to use it (about); both are required strings.

Continuous integration¶

Workflow

Trigger

What it does

pr.yml

Pull requests to master that change more than Markdown

Runs build-yocto.yml with the pr profile and records which workflow run belongs to the pull request.

push.yml, nightly-build.yml, weekly-build.yml

Pushes to master; nightly except Saturday; Saturday

Build, test on LAVA boards, and publish results; the weekly profile adds the costly builds.

nightly-build-wrynose.yml

Daily

Starts the nightly build on wrynose.

build-yocto.yml, compile.yml

Called by the build workflows

Lock the kas files, run yocto-patchreview, yocto-check-layer, and oe-selftest, and build each machine, distribution, and kernel combination.

test.yml, test-distro.yml, test-pr.yml, test-pr-wrynose.yml, publish-results.yml

After builds, and after “Build on PR” completes

Submit LAVA test jobs with the actions, comment on pull requests, and publish the “Test Results” check.

markdownlint.yml, repolinter.yml, documentation.yml

Pull requests and pushes to master

Lint Markdown, check the organisation’s repository rules, and rebuild and check this documentation.

backport.yml

Merged pull requests to master labelled backport wrynose

Opens the backport pull request.

stales.yml, sstate-cleanup.yml

Daily; weekly

Mark inactive issues and pull requests stale; expire unused shared state files.

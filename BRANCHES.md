# Branches

This page describes each branch of
[qualcomm-linux/meta-qcom](https://github.com/qualcomm-linux/meta-qcom/branches)
and how it relates to `master`. Support status comes from the Yocto Project's
[releases page](https://wiki.yoctoproject.org/wiki/Releases); last activity is
the date of the branch's latest commit when this page was written.

| Branch | Purpose | Status | Build from it | Contributions | Relationship to master |
| --- | --- | --- | --- | --- | --- |
| `master` | Primary development branch, with focus on upstream support and compatibility with the most recent Yocto Project release. | Active; declares compatibility with wrynose. | Yes | Pull requests, as [CONTRIBUTING.md](CONTRIBUTING.md) describes. | Main branch. |
| `wrynose` | LTS branch based on the Yocto Project 6.0 release, used by Qualcomm Linux 2.x. | Active; Yocto Project support until April 2030. | Yes, with wrynose layers. | Fixes land on `master` first and are backported, as [CONTRIBUTING.md](CONTRIBUTING.md) describes. | Maintained separately; receives backports from `master`. |
| `backport/<pr>-to-wrynose` | Created by [backport.yml](.github/workflows/backport.yml) from a merged `master` pull request labelled `backport wrynose`. | Temporary: one per backport pull request. | Only to test the backport. | Review them in their backport pull requests. | Carry `master` commits into `wrynose`. |
| `next` | For testing workflow changes before being merged to master, according to the branch's own [README](https://github.com/qualcomm-linux/meta-qcom/blob/next/README.md). | Last activity September 2026. Not documented otherwise. | Builds like `master`; meant for workflow tests. | Not documented. | Changes are intended to merge into `master`. |
| `kirkstone` | Legacy branch maintained by Linaro, prior to the migration to [qualcomm-linux](https://github.com/qualcomm-linux), for the Yocto Project 4.0 release. | Yocto Project support ended; last activity December 2024. | Only with kirkstone layers; it holds 14 machine configurations. | Not open for direct contributions; raise an issue with the suggested change instead. Its own [README](https://github.com/qualcomm-linux/meta-qcom/blob/kirkstone/README.md) still names pull requests to [Linaro/meta-qcom](https://github.com/Linaro/meta-qcom), which now redirects here. | Does not merge into `master`; maintenance is not documented. |
| `dunfell`, `scarthgap`, `styhead` | Legacy branches maintained by Linaro, prior to the migration, for the Yocto Project 3.1, 5.0, and 5.1 releases. | dunfell: support ended, last activity December 2024. scarthgap: Yocto Project support until April 2028, last activity December 2024. styhead: support ended, last activity January 2025. | Only with the matching release's layers; dunfell holds 13 machine configurations, scarthgap and styhead the generic `qcom-armv7a`, `qcom-armv7a-modem`, and `qcom-armv8a` machines. | Their READMEs ([dunfell](https://github.com/qualcomm-linux/meta-qcom/blob/dunfell/README.md), [scarthgap](https://github.com/qualcomm-linux/meta-qcom/blob/scarthgap/README.md), [styhead](https://github.com/qualcomm-linux/meta-qcom/blob/styhead/README.md)) name pull requests to [Linaro/meta-qcom](https://github.com/Linaro/meta-qcom), which now redirects here; the current policy is not documented. | Does not merge into `master`; maintenance is not documented. |
| `honister`, `jethro`, `krogoth`, `morty`, `pyro`, `rocko`, `sumo`, `thud`, `warrior`, `zeus` | Legacy branches maintained by Linaro, prior to the migration, for the Yocto Project release of the same name. | Yocto Project support ended; last activity between 2016 and 2024. | Only with the matching release's layers; each holds 4 to 13 machine configurations. | Their READMEs, such as [honister's](https://github.com/qualcomm-linux/meta-qcom/blob/honister/README.md), name pull requests to [ndechesne/meta-qcom](https://github.com/ndechesne/meta-qcom) or patches to the `openembedded@lists.linaro.org` list; the current policy is not documented. | Does not merge into `master`; maintenance is not documented. |
